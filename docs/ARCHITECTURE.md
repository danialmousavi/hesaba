# معماری حسابا

## وضعیت فعلی

- برنامه با Next.js App Router، TypeScript و Tailwind اجرا می‌شود. اجرای Next.js روی سیستم کاربر است؛ PostgreSQL می‌تواند در Docker اجرا شود.
- داده‌ها در PostgreSQL و از طریق Prisma و PostgreSQL adapter خوانده و نوشته می‌شوند. `lib/prisma.ts` اتصال مشترک سمت سرور است؛ migrationها در `prisma/migrations/` هستند.
- Better Auth، صفحه‌های ثبت‌نام/ورود، خروج و ایجاد سازمان وجود دارند. زیرساخت و رابط انتخاب سازمان فعال در دیتابیس ایزوله آزمایشی فعال است؛ اجرای عادی هنوز نخستین عضویت کاربر را بر اساس زمان ایجاد انتخاب می‌کند.
- API خصوصی `GET /api/profile` پروفایل نشست فعلی را برمی‌گرداند. ویرایش نام و تغییر رمز از endpointهای استاندارد Better Auth (`/api/auth/update-user` و `/api/auth/change-password`) انجام می‌شود و رابط آن در `/dashboard/profile` موجود است.
- صفحات در `app/(app)/` و APIها در `app/api/` هستند. اعتبارسنجی با Zod انجام می‌شود و منطق دامنه فعلاً عمدتاً در Route Handlerهاست؛ لایه مستقل `services/` در ساختار فعلی وجود ندارد.
- ثبت سازمان از Server Action استفاده می‌کند؛ سایر عملیات اصلی موجود از Route Handler استفاده می‌کنند. برخی صفحات داده را مستقیماً در Server Component می‌خوانند و قسمت‌های تعاملی Client Component هستند.
- مبالغ دفاتر و قیمت کالا `Decimal(20,0)` و به ریال هستند؛ خروجی مبلغ گزارش‌ها رشته است تا دقت حفظ شود. تاریخ‌های مالی `date` ذخیره و در رابط با تقویم شمسی نمایش داده می‌شوند.
- نقش‌ها و سازمان در مسیرهای موجود سمت سرور بررسی می‌شوند. سند نهایی با trigger در برابر تغییرهای معمول محافظت می‌شود؛ جزئیات و محدودیت‌ها در [DATABASE.md](./DATABASE.md) آمده است.
- فونت‌های محلی پروژه استفاده می‌شوند. نمودار ماهانه با اجزای موجود و بدون کتابخانه نمودار پیاده شده است؛ Recharts، shadcn/ui و React Hook Form در وابستگی‌های فعلی نصب نیستند.

## اجزای موجود

| جزء | وضعیت |
|---|---|
| سال مالی و کدینگ | ایجاد و مدیریت سال، بستن سال و مدیریت درخت حساب |
| اسناد | پیش‌نویس، ویرایش، حذف و ثبت نهایی؛ رویدادهای سند و محدودیت تغییر اسناد نهایی |
| گزارش | تراز آزمایشی، دفتر کل، سود و زیان و خلاصه/گردش ماهانه داشبورد |
| اشخاص | مدل، API و رابط ثبت، فهرست، ویرایش و تغییر وضعیت |
| کالا و خدمات | مدل، API و رابط ثبت، فهرست، ویرایش و تغییر وضعیت موجود است |

## محدودیت‌ها و طراحی آینده

- مدل، API و رابط ایجاد، ویرایش، فهرست، مشاهده و حذف پیش‌نویس فاکتور، صدور نسیه و ابطال فاکتور بدون تخصیص دریافت در سال مالی باز موجودند. API و رابط ثبت دریافت مشتری و تخصیص به فاکتور و پرداخت تأمین‌کننده همراه سند و گزارش مانده اشخاص موجودند. مدل، API و رابط پیش‌نویس، ویرایش و ثبت نهایی درآمد/هزینه و فهرست مستقل رویدادهای ثبت‌شده با سند مرتبط نیز موجودند. تخصیص پرداخت به فاکتور خرید هنوز پشتیبانی نمی‌شود.
- دکمه بستن ساده سال جایگزین اختتامیه و انتقال مانده نیست؛ API و رابط اختصاصی اختتامیه و افتتاحیه ایجاد می‌کنند. برگشت سند مستقل و ابطال محدود فاکتور موجود است؛ اصلاح دریافت، پرداخت و درآمد/هزینه باقی است. گزارش عملکرد ردیف‌های بستن حساب موقت را حذف می‌کند.
- دستیار Ollama، ابزارهای AI و تأیید اقدامات هنوز پیاده‌سازی نشده‌اند؛ [AI_DESIGN.md](./AI_DESIGN.md) طراحی پیشنهادی است.
- APIها، صفحات سروری و رابط به زیرساخت آزمایشی سازمان فعال متصل شده‌اند؛ فهرست، افزودن، تغییر نقش و حذف دسترسی عضو نیز در همان محیط در صفحه «سازمان من» موجود است. این قابلیت‌ها برای کاربران عادی غیرفعال‌اند و اجرای عادی همچنان عضویت اول را استفاده می‌کند. [طرح سازمان فعال](./ACTIVE_ORGANIZATION_DESIGN.md) و [طرح مدیریت اعضا](./MEMBERSHIP_MANAGEMENT_DESIGN.md) قراردادهای این بسته را مشخص می‌کنند.
- اطلاعات گزارش‌ها و داشبورد تابع سازمان انتخاب‌شده با روش عضویت اول هستند. خروجی ماهانه تنها ماه‌های دارای گردش را برمی‌گرداند و نمودار همین ماه‌ها را نشان می‌دهد.
- برخی تست‌های مرتبط با هم‌زمانی و بررسی بصری مرورگر باقی مانده‌اند؛ وضعیت دقیق در [TASKS.md](./TASKS.md) است.
